# Mouse wheel methods

Use an isolated O: worktree and request the current resource owner's browser/compiler grant before running. Cargo stays at -j2; use the existing 1.85.1 toolchain and installed wasm32 target. Set TEMP/TMP to the owned worktree tmp directory. Do not invoke an uninstalled +stable alias or install duplicate reference dependencies.

Run `MOUSE_CASE_FAMILY=wheel-methods XT_REFERENCE_ROOT=/existing/source_repo node scripts/mouse-mode-source.mjs` to compare seven unchanged-source captures across Chromium, Firefox and WebKit. First creation of new fixtures uses `--generate`, after inspecting their original-source outputs. Never regenerate fixtures merely to accept a Rust mismatch.

Run `WASM_TEST=wasm_terminal_mouse_wheel_methods node scripts/browser-host-check.mjs`, with WASM_BINDGEN pointing to the existing 0.2.100 CLI and PLAYWRIGHT_MODULE pointing to an existing compatible reference installation. This calls actual Rust Terminal, not a mock or the JavaScript terminal engine. The cases cover raw handler/return/thrown values, borrowed receivers, two accessor reads, reentry, prototype identity, public and service replacement, both DOM wheel routes, overrides and retention across reset/dispose.

Run regressions `wasm_terminal_wheel_receiver`, `wasm_terminal_mouse_modes`, `wasm_terminal_mouse_builtins`, `wasm_terminal_mouse_disposal`, and `wasm_terminal_mouse_names` sequentially through the same runner and grant. Preserve raw reports, count functions separately from source operations, pin source/build artifacts, then clean owned generated artifacts. Full raw protocol/encoding registry task305 and overall equivalence remain open.
