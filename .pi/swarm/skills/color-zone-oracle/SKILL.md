# Color zone oracle

Run from repository root with Node24.15+, reference dependencies and Rust1.85+. Check shared disk headroom, use finite command timeouts and keep the existing shared target directory/profiles.

```sh
node scripts/color-zone-oracle.mjs
cargo test -p xterm-web --test color_zone_store --test color_zone_differential
cargo clippy -p xterm-web --test color_zone_store --test color_zone_differential -- -D warnings
```

Default oracle execution verifies deterministic fixture bytes without rewriting them. Use `node scripts/color-zone-oracle.mjs --generate` only when deliberately generating fixtures from unchanged source. A mismatch writes actual generated bytes under tmp/color-zone-oracle/actual.tsv and fails. Do not hand-edit expected rows to conceal a mismatch.

The script uses upstream esbuild and actual Mocha to execute all three untouched original ColorZoneStore assertions. It records source hashes, exact outcomes, Node/platform metadata, seed0xc01020ae and2048 operation snapshots under results/color-zone. Snapshots compare ordered zone values, pool object identities and retained old handles after clear/reuse. Colors include a lone UTF16 surrogate. The source algorithm extends only its first matching zone and never coalesces every overlapping zone.

Native tests port the three original assertions and cover defaults/missing settings, each position, fractional/negative/missing/NaN padding, nonfinite lines, external shared mutation, pool trimming and recoverable Rust borrow errors. Browser overview canvas pixels and DOM decorations belong to task32, not this portable store check. No native Linux/macOS or browser equivalence follows from Windows execution.
