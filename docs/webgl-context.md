# WebGL canvas and context lifecycle

`webgl::canvas_context::CanvasContext` creates an actual HTML canvas and WebGL2 context before any renderer subscriptions. Context attributes preserve `antialias: false`, `depth: false`, and the explicit undefined or boolean `preserveDrawingBuffer` value. Falsy context returns, including undefined, false, NaN and zero BigInt, produce the source's concatenated error message before context listeners or observers exist. A minimal catching JavaScript operator binding preserves that concatenation; Rust owns all lifecycle decisions. The canvas comes from the supplied main document, including when its owning window differs from the terminal's current browser window.

`webgl::context_lifecycle::ContextLifecycle` installs the original WebglRenderer context event phases, the existing DevicePixelObserver component, live browser-window replacement, and the main-document mousedown cursor restart. Callers supply live terminal rows, logging, cursor restart and the renderer's restoration operation. Restoration must release the terminal from the existing shared atlas cache and reinitialize GPU state before returning. The lifecycle then requests a full asynchronous viewport redraw. It does not create another atlas pool or initialize fake GPU resources.

Loss logs first, prevents the original event's default, and schedules the source-global 3000ms timeout. It does not use a terminal's iframe window timers. Expiry clears the stored handle before logging and forwarding the original event identity. Restoration logs, clears the current global timeout, clears the handle, invokes restoration, and requests redraw. Every host error stops that sequence with the already-performed state mutations retained. Repeated loss deliberately does not cancel the previous timeout, matching the supplied source. Clearing an undefined handle is still an observable host call.

Physical observer resizing compares raw width first and reads height only if that comparison matches. Both setters run whenever either dimension differs. Canvas conversion happens separately at each setter, so a height conversion error leaves the width changed. Only successful changes request synchronous redraw. This operation does not change logical renderer dimensions or the cell-grid-derived GPU viewport.

Observer replacement constructs and starts the new observer before disposing the old one, but adopts it only after old disposal succeeds. No lifecycle RefCell borrow spans a host call, observer disconnect, emitter callback or renderer operation. Explicit disposal is idempotent and stops at the first error. It disposes the observer before emitters and context listeners, then the window subscription and document listener, and finally clears the timeout. The enclosing renderer must then dispose its layers, call `CanvasContext::detach`, and release its atlas in the original order. GPU resources have their own existing RAII owners.

The final Rust owner attempts lifecycle cleanup if explicit disposal has not already been attempted. The last CanvasContext owner separately detaches its canvas unless detachment was already attempted. Reattaching after explicit detach starts a new owned attachment. JS-owned event/timer callbacks hold only weak state. After last-owner drop, retained callbacks cannot keep the renderer alive or invoke dead Rust. Failed constructor cleanup and ignored-after-disposal observer assignment use RAII rather than intentionally preserving the source's leaked registrations. These are resource-safety differences, not proven leak equivalence. Arbitrary replacement/proxy DOM interfaces and raw substituted browser services are outside this typed browser component's contract.

## Verification

The focused WASM suite compares 29 shared lifecycle scenarios against the unchanged original WebglRenderer constructor closures and methods. A separately hashed test wrapper uses the actual original public Terminal and browser services. It bypasses GPU/model initialization on the source side only, because those operations are not implemented by this component. The original getContext call, event closures, resize, DevicePixelObserver, MutableDisposable and disposal remain in use. Deterministic phase cases replace getContext with a controlled return of one actual WebGL2 object, or a directed falsy/throwing value. They assert argument own-property descriptors, read/call/error phases and actual HTMLCanvasElement mutation, not framebuffer drawing. Reusing that object avoids WebKit's context quota while keeping every phase assertion. The separate native tests do not substitute getContext; they assert real per-canvas context identity, options, RGBA pixels and browser-generated loss/restoration events. Rust uses the real CoreBrowserService, CanvasContext and ContextLifecycle, not a fake terminal `_core`.

A separate Rust ownership test verifies last-owner observer disconnect, timer cancellation, canvas detachment and inert retained timer callbacks. This tests resource safety, not the source's leaks. Separate real GPU checks compare RGBA readback, actual per-canvas context identity and explicit preservation options. A native context-cycle test requests `WEBGL_lose_context`, awaits actual loss/restoration events with a bounded deadline, and checks event cancellation, restoration callback order and the final redraw. Unsupported extension availability is a reported failure, not an ignored pass. Synchronous observer resize notifications are excluded only from this native context-cycle trace; the separate deterministic resize cases assert them directly. A real animation frame separates loss-event dispatch completion from the extension's restore request, as Chromium and WebKit require. This is not a sleep or retry.
