# Terminal OSC input acceptance

Scope is the OSC registrations in `source_repo/src/common/InputHandler.ts` and its `setTitle`, `setIconName`, `setOrReportIndexedColor`, `setHyperlink`, special-color and restore methods. Color parsing is covered separately by criteria117/118; the shared link store by247-249. This task must exercise actual parser and terminal state, not call those utilities alone.

OSC01. Register exactly source handlers 0/1/2/4/8/10/11/12/104/110/111/112. Accept BEL and ST, including chunk splits before/within/after payload and terminators. Preserve abort and 10,000,000 UTF-16 payload-limit behavior inherited from OscHandler. Unknown identifiers still bubble to existing fallback. A custom handler registered later has source precedence; false and asynchronous false resume into these handlers without replaying bytes.

OSC02. Store title and icon strings as UTF-16, including empty input, astral characters and isolated surrogates. OSC2 emits one title event even when the value is unchanged. OSC1 updates icon only. OSC0 sets/emits title before updating icon. A title listener must see the new title and previous icon, not an already-batched icon update. Listener errors stop remaining side effects. CSI22/23 title stacks and source ten-entry limits are separate engine/window responsibilities but must call the same title/icon helpers.

OSC03. OSC4 consumes complete index/spec pairs left-to-right, ignoring a trailing unpaired slot. An index must contain one or more ASCII decimal digits and fall in0..255. Leading zeroes are valid. Signs, spaces, decimal points, Unicode digits, empty slots and overflow are invalid. A '?' spec produces Report. Valid X11 specs produce Set. Invalid pairs are skipped without shifting later pairing. All valid requests from one OSC4 are emitted as one ordered batch. No event is emitted for an empty batch.

OSC04. OSC10/11/12 map to special indices256/257/258 respectively. Every semicolon slot advances the index, even an empty or invalid spec. Ignore parameters beyond cursor. Emit each valid Set/Report in its own one-element event, not one combined batch. Dispatch callbacks before processing the next event so failures or reentrant observations cannot see future events prematurely.

OSC05. Empty OSC104 emits one Restore with no index, meaning all indexed palette slots. Nonempty data is split into independent decimal indices with the exact OSC4 digit/range rules. Preserve duplicates and order in a single batch. Whitespace-only data is not empty and does not reset the palette. OSC110/111/112 always emit their matching special Restore, regardless of payload.

OSC06. Color requests do not change a made-up core palette or synthesize replies in headless mode. They go through the real internal color event. Browser integration must apply Set/Restore to the live ThemeService, and Report must respond with the current theme color and exact OSC response. A raw native observer can implement its own host policy. Real browser replies and palette/canvas behavior are separate task31/32 gates and must be tested there.

OSC07. OSC8 splits at the first semicolon only, preserving every subsequent semicolon in the URI. No semicolon is handled=true with no changes. Trim only the params using ECMAScript whitespace. Nonempty URI opens a link even if it is not a recognized browser URL scheme. Empty URI plus nonempty trimmed params returns false and retains the current link. Empty URI plus empty params finishes the link. Do not apply browser URL validation inside this parser.

OSC08. Opening a link finishes a previous nonzero link first, then parses colon-separated params. Only the first segment beginning exactly 'id=' is used; empty id becomes absent. Ignore unknown params and later id segments. Params/id/URI must preserve UTF-16 and lone surrogates. Clone extended attributes before URL mutation so existing cell objects do not change, drop payload as source clone does, and update HAS_EXTENDED. Closing sets URL id0 while preserving other clone fields. Service errors cannot return a successful handled result.

OSC09. Print uses this same link service: every source print codepoint registers the current absolute line before the wrap check, not only the first character or after wrapping. Test wide cells, wrap, combining joins, soft hyphens, cursor motion, normal/alt buffers and trim expiration. Compare cell URL ids, extended identity and lookup data. All valid JS link ids up to2^53 must survive the cell carrier without u32 truncation. Browser link lookup and disposal remain required by criterion250.

OSC10. Port all source OSC assertion bodies in InputHandler.test.ts lines2141-2310 with unchanged expectations and exact counts, including hyperlink semicolons. Run original applicable cases against the original dependencies. Add directed matrices for OSC01-09 and deterministic seeded JS/Rust sequences comparing color event grouping, title/icon event-time snapshots, handled results, full linked cells and marker lookup lifetimes. Keep counterexamples and source/workload hashes.

OSC11. Run focused Rust tests, warning-free Clippy and rustfmt, retain runtime/commands/counts/failures, and obtain independent review. Other native platforms, real browser colors/links and full terminal equivalence stay unproven until observed. Temporary shared build failures are integration work, never an external blocked equivalence claim.
