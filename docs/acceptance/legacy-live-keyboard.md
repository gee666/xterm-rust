# Live legacy keyboard acceptance

Task155 extends the accepted immutable event port without changing its native API. It covers `source_repo/src/common/input/Keyboard.ts`. A browser event can expose getters that change values or throw. The original evaluator reads those properties at each expression, not once at entry. `KeyboardEventSource` must preserve this behavior through a fallible Rust entrypoint.

The native `KeyboardEvent` still uses borrowed UTF16 and u32 keyCode. Its adapter is infallible. `try_evaluate_keyboard_event` accepts live getters returning f64 keyCode, borrowed-or-owned UTF16 key/code and booleans. It returns the exact generic error value without formatting or substituting a policy fallback.

## Getter paths and failure boundaries

LK01. Initial modifier reads occur Shift, Alt, Control, Meta, exactly once each before the switch's keyCode read. They form a saved mask. Later modifier getters do not retroactively change that mask.

LK02. A special-key switch reads keyCode once. NaN, infinities, negative and fractional values do not accidentally match integral cases through a Rust cast. Negative zero matches zero. Special branches must not read unused key/code getters.

LK03. Mobile code0 reads key separately for Up, Left, Right and Down comparisons in that order until a comparison succeeds. A getter may return a different name at each comparison. No modifier getter beyond the initial mask is needed there.

LK04. Backspace reads Control then Alt. Tab reads Shift, with no unused code getter. Enter reads key then conditionally Control for lowercase c, otherwise Alt. Escape reads Alt. Arrow branches read Meta before selecting a saved-mask sequence. Insert short-circuits Shift then Control. Page keys read Shift then conditional Control. Home/End/Delete/F keys use only the saved mask after the switch.

LK05. Default Control-only gating reads Control, Shift, Alt, Meta in order, stopping at the first false condition. Letter range checks each read keyCode independently; the fromCharCode arithmetic reads it again. Space, digit-range, 8, slash and bracket conditions preserve original priority and individual reads. A changing final numeric getter is not assumed still to satisfy earlier range comparisons.

LK06. The eligible Alt branch reads keyCode for the US lookup. Shift is read for the mapping index only when that lookup exists. Otherwise letter range checks, Control choice, final keyCode arithmetic and Shift-uppercase check each keep their own source reads. Space and Dead-key paths run only after those branches fail.

LK07. Dead-key detection reads key, then code for startsWith. The slice reads code again. It takes unit3 before the Shift getter and keeps that unit even if Shift's getter mutates code afterward. Empty slices, lone surrogates, astral prefixes and Unicode expansions remain lossless. A second code value need not still start with Key.

LK08. Mac selection gating reads Alt, Control, Shift, Meta in that order and only then keyCode. Platform and option booleans short-circuit the same expressions as JS. Getter failures from branches that are not evaluated must not appear.

LK09. Printable fallback reads key for truthiness, Control/Alt/Meta, keyCode, key again for length, then key a third time for the emitted payload. The last payload can differ in length/content from the tested value. Ctrl+Shift fallback separately reads key, Control, Shift and code once for its switch.

LK10. Throw at every getter boundary reached by a successful case. Compare the exact preceding reads and stop position. Return the same error object. No later getter, case conversion or payload construction is allowed after a failure. Native getters cannot fail and keep the existing function signature.

## Number and Unicode behavior

LK11. f64 default-branch comparisons preserve fractional values and NaN rather than coercing them to a DOM u32 early. String.fromCharCode performs ToUint16 on the arithmetic result. Test negative, signed zero, values around65/90/51/55, fractions, 65535/65536, values beyond2^53, infinities and NaN. Tests must include changing range and final-arithmetic getter values.

LK12. A changing final Alt-letter getter can select a non-ASCII UTF16 unit. Shift then invokes full JS uppercase on that unit, including expansions such as sharp-s to SS. The pinned Unicode17.0 uppercase table is generated by the same oracle runtime as lowercase and retains Unicode attribution. Check table completeness and all BMP mapping data, not only ASCII. Stable native letters must remain unchanged.

LK13. Lowercase and uppercase use whole resulting UTF16 strings where upstream does. Dead-key slice still selects only one input unit, and Kitty's first-code-unit helper remains separate. Preserve U+0130 expansion, Unicode17 mappings, unpaired surrogates and empty payload versus undefined.
