# Nested render callback iteration

Task499 repairs the callback array used by RenderDebouncer. The source for-of loop retains its original array throughout iteration. A successful nested frame replaces the current callback list with a new array, but the outer iterator must still visit the original array's remaining entries and live appends. Outer success replaces the current list again, including callbacks appended after the nested replacement. An exception skips that final replacement and preserves whichever list is currently installed.

Rust now gives each callback list shared identity. Frame dispatch captures that list after the render callback and before callback iteration. It releases all list borrows before entering callbacks and replaces only the current list on successful completion. This keeps callback order and error state without copying callback entries or holding mutable borrows across callbacks. BrowserRenderDebouncer uses an immutable Fn closure, since a custom reentrant host can deliver a second outstanding frame while the same Rust dispatch function is active. The source installs separate closures for each request, which do not have wasm-bindgen's FnMut reentry guard.

No dependency, unsafe code, original-source edit or JavaScript engine fallback is added. Timer blocks are unchanged. Accepted486 timer changes must compose by their owned hunks, not a whole-file replacement.
