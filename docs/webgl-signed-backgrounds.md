# Signed backgrounds in the glyph GPU

Task462 connects task449's exact numeric backgrounds to the real glyph renderer's overlap clipping. `GlyphColorNumbers` now lives with glyph geometry. `renderer_types::GlyphColorNumbers` remains a public reexport, so existing `UpdateHost` implementations do not change.

`GlyphGeometry::update_cell_with_colors` and `GlyphRenderer::update_cell_with_colors` compare the original background numbers before clipping. For example, JavaScript considers `2147483648 !== -2147483648` true although both values pack to `0x80000000`. The old GPU consumer compared only those packed words and incorrectly drew a left overhang. Page-width lookup and vertex generation now use the same numeric comparison. Existing `update_cell` entry points delegate with unsigned numbers inferred from `GlyphCell`, preserving their previous contract without duplicating geometry or GPU work.

A future actual browser `UpdateHost::update_glyph` must pass its `numbers` argument directly to the new GPU entry point. Do not reconstruct it from packed model words. This change does not implement that browser host. Atlas lookup still consumes the existing packed `GlyphCell` contract, and raw JavaScript atlas numeric cache identity and getter/reentry phases remain in306. No new dependency, unsafe code, constructor fallback or JS terminal delegation is introduced.

## Regression scope

`scripts/webgl-glyph-oracle.mjs` still generates the original147-case fixture byte-identically, including128 seeded cases with seed `0x61ab9423`. It additionally generates `webgl-glyph-backgrounds.json` by invoking the unchanged original `GlyphRenderer.updateCell` with eight signed/unsigned background pairs. Four pairs have identical packed words but unequal numbers, and four pairs are numerically equal controls. The fixture retains imported-source hashes, complete Float32 vertex snapshots and compact uploads.

The new native test compares every vertex/upload word against that separate source fixture, including all equal controls. The actual GPU regression draws all eight pairs, checks the overhang pixel and the surviving cell pixel, and requires WebGL2. Existing seven GPU tests retain all original assertions, including147-case real GPU uploads, atlas routing, lifecycle, context loss and resource cleanup. This is component evidence, not full WebglAddon or unchanged full addon/demo suite coverage.

Observed Windows/MSRV1.85.1 results: eight native tests passed with default features and eight with all features; the new signed fixture passed in release. Strict Clippy passed for the library and focused native/WASM targets. All eight actual GPU tests passed in each of Chromium, Firefox and WebKit, zero ignored or filtered. Restoring the old unsigned comparison failed exactly the new native test and exactly one of eight Chromium GPU tests. The negative harness restored and hash-verified production bytes in `finally` before fresh native and all-three-engine passes. The audit checked776 original reference hashes,34 inherited449 pins and27 new source/evidence pins.
