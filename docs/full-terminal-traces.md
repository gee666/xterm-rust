# Rich terminal trace contract

Task157 adds richer completed-step captures without changing the shared `terminal-snapshot.mjs` fixture schema used by earlier handler suites. `scripts/full-trace-runner.mjs` exports `runTrace(context, traces)` for explicit User case adapters. `context` has the acceptance worker's `root`, `outputDirectory` and `signal`.

A trace is:

```js
{
  id: 'named-directed-case',
  cols: 5,
  rows: 3,
  scrollback: 6,
  ops: [
    ['O', 'screenReaderMode', true],
    ['W', 'a界e\u0301'],
    ['B', [0xf0, 0x9f, 0x99, 0x82]],
    ['R', 4, 2],
    ['O', 'windowOptions', { pushTitle: true, popTitle: true }],
    ['S', -1],
    ['C'],
    ['Q']
  ]
}
```

The helper returns `sourceHashes`, `artifactHashes`, command receipts and one native `captures` entry. The caller adds its exact `caseId`. Each call allocates its own output subdirectory, even when a case calls the helper more than once. It never reuses a prior successful output.

## Native CLI and protocol

`cargo build -p xterm-core --example full_trace --message-format=json` identifies the actual built executable. The helper does not guess a target location or create another Cargo target directory. Invoke that artifact as `full_trace INPUT.tsv OUTPUT.tsv`.

The ASCII TSV protocol preserves original strings as raw UTF-16 units, never lossy UTF-8:

| Command | Fields after command |
| --- | --- |
| N | columns, rows, scrollback; creates a fresh terminal and emits no snapshot |
| W | comma-separated UTF-16 hex units, empty string allowed |
| B | comma-separated byte hex values, each at most ff |
| R | columns, rows |
| S | signed scroll-line count |
| C | no fields, public clear |
| Q | no fields, public reset |
| O | option key, value kind, encoded value |

Option kinds are `b` for boolean0/1, `n` for a number, `s` for UTF-16 hex strings and `m` for a boolean property bag such as `pushTitle=1,popTitle=0`. This is an explicit trace protocol, not a substitute for the full JavaScript options boundary. Invalid protocol operations fail instead of becoming successful no-ops.

Every non-construction operation emits one rich snapshot plus its ordered event string. Source and native runners consume the same input file independently. The source runner bundles the unchanged headless Terminal and Charsets definitions together so built-in charset identity remains observable. Original source hashes are retained. The Rust artifact never calls the JS implementation.

## Compared domain

The capture retains both complete buffers, every line's wrap flag and every cell's packed content, width, UTF-16 text, foreground/background, extended attributes and URL ID. It also retains active buffer, both cursors, scroll margins, scrollback base/viewport, saved cursor, saved attributes, saved charset and designation slots, saved origin/wrap flags, tab stops and capacity. Active charset identity, designation level, title/icon text, core mode bits, cursor style/blink, visibility, initialization and Unicode version are compared.

A separate ordered stream records bell, cursor, linefeed, public scroll, data replies, binary, title, resize/render, reset/synchronization/focus/window-report and accessibility observations. The source listeners and native enum projection use the same tokens. A mismatch is retained, not normalized away. In particular, known reset notification-order differences remain failures until the engine owner fixes the actual behavior.

`WriteParsed` belongs to asynchronous host-queue/public API tests rather than these completed handler steps. Browser-only InputScroll forwarding remains a separate selection/viewport gate. Color-query events are outside these print/control cases and cause an explicit unsupported-capture error on the native side; they are not silently accepted. This helper does not claim arbitrary custom-map identity or every public callback/lifecycle contract.

The normalized capture has the fields required by the unified VT runner: `cells`, `cursor`, `margins`, `normal`, `alternate`, `events` and `replies`, plus additional properties. Cells are stored once per side. The normal/alternate fields retain the remaining buffer metadata rather than duplicating those arrays.

Complete independent captures are written before the equality assertions, so a failed comparison retains both sides. The first divergent operation index is reported. The protocol file, named scenarios, exact command logs, source hashes, executable hash and Rust toolchain version accompany the capture.

## Case ownership

`terminal/fulltraces.cases.mjs` owns only vt23/24/44/45/46. Their directed matrices are generated by `full-trace-scenarios.mjs`: right-edge printing in wrap/insert modes, soft hyphen/REP, LF/VT/FF with margins and convertEol, IND/NEL/RI including C1 forms, and bell/carriage return after Unicode and pending wrap. UTF-16-unit and UTF-8-byte partitions are included for the printing cases. Screen-reader mode makes accessibility output observable.

Coleman's reply/window adapter owns vt32/33/35/36/37/38/39/42/43 and can reuse this helper. Other adapters must not register those IDs again. The root terminal adapter rejects duplicates and missing cases.

## Execution status

All five native/source matrices pass in the Alaric worktree: vt23 2,544 comparisons, vt24 888, vt44 2,256, vt45 1,880 and vt46 750. Total: 1,236 scenarios and 8,318 full-state comparisons, with no skipped runtimes. Six protocol/projection tests and the reverse-index regression also pass. The vt45 matrix found a real RI render-range defect: only the active scroll region should be refreshed. The engine fix and a regression for normal/alternate buffers preserve that source behavior. Earlier failures remain available, not normalized away. These are native finite-corpus results, not browser/WASM or complete terminal equivalence. The helper checks the shared 1024MiB reserve and uses bounded, owned child processes. Actual native and source case receipts are required before acceptance. Browser/WASM and native Linux/macOS evidence remain separate.
