# Independent serializer oracle

This verifies the Rust ANSI and HTML serializer functions against the supplied xterm.js 6.0.0 source. It does not claim that Rust terminal parsing, addon activation or browser bindings are complete.

## Commands

Install the reference dependencies as described by the repository setup instructions, then run from the repository root:

```sh
node scripts/serialize-oracle.mjs
cargo test -p xterm-core --test serialize_differential
cargo test -p xterm-core --release --test serialize_differential
cargo clippy -p xterm-core --lib --test serialize_differential -- -D warnings
rustfmt --edition 2021 --check crates/xterm-core/tests/serialize_differential.rs crates/xterm-core/tests/support/serialize_fixture.rs
```

Node v24.15.0, esbuild 0.28.1 and Mocha 11.7.6 from `source_repo/node_modules` are used for the retained baseline. The precise observed versions are in `results/serialize/oracle.json`. Use the workspace Cargo profiles and shared target directory. Check free space before building. The fixture is generated data, not hand-maintained test code.

## Original assertions

The generator bundles the original `source_repo/addons/addon-serialize/src/SerializeAddon.test.ts` and its dependencies under `tmp/serialize-oracle/`. Experimental decorator handling follows the original browser compiler configuration. Imports for `common` and `browser` resolve to the supplied source tree. It does not rewrite source implementation statements or assertion bodies.

An observer subclass calls each unchanged source serialization method and records its terminal input and exact return value or error. Its return value and thrown error still reach the original assertion. Chai `equal`, `notEqual` and `ok` retain their implementations; wrappers count calls per original test. Mocha executes the original async hooks and write callbacks.

The observed suite discovers, executes and passes all 44 original tests, with 60 Chai assertion calls. No cases are pending, skipped or unrun. Every original test makes one serializer call, yielding 18 ANSI and 26 HTML snapshots. The report maps every original test name, observed assertion count and fixture index. SHA-256 hashes identify all 111 original source/test inputs used by the bundle, without inventing an upstream commit hash.

The Rust differential suite compares every captured serializer result exactly. This is stronger than each output substring assertion for that same snapshot, but does not migrate assertions about the JS terminal engine itself. In particular, the original scroll-region and hidden-cursor round-trip tests still execute against JavaScript. Their Rust terminal round-trip counterparts, pre-serialization terminal state assertions and WASM addon lifecycle tests remain required by task 88 and `docs/serialize-acceptance.md`.

## Directed and seeded inputs

The corpus contains 3,334 independent serializer outputs:

- 44 results captured from the original suite.
- 1,242 directed outputs from 621 terminal-state cases. These cover every P16 and P256 foreground and background index with palette-to-RGB-to-default transitions, all nine flags, six underline styles with five color configurations, empty/space/combined/non-BMP/lone-surrogate/NUL cells, colored null gaps, natural and forced wraps, ranges, scrollback boundaries and individual modes.
- 2,048 outputs from 1,024 raw buffer-state cases generated by xorshift32 with seed `0x05e21a11`, decimal 98703889. Dimensions, scrollback, wide placeholders, raw UTF-16 strings, colors/flags, underline attributes, wrapping, cursor state, current input attributes, modes, selection and range options vary deterministically.

There are 1,663 ANSI and 1,671 HTML outputs. The source throws `Invalid array length` in 180 snapshots, which Rust must return as the documented `SerializeError::InvalidRange`. One out-of-buffer inclusive range throws a TypeError when the source reads `isWrapped` on a missing next line. Rust must preserve this as the distinct `MissingWrappedLine` failure, not successful output or an unrelated range error. Captured messages are Node/V8 text; browser bindings still need to preserve error categories in each supported engine. Errors are not counted as skipped cases. The colored-null-gap directed fixture confirms the exact sequence `ESC[42m ESC[3X ESC[3C x ESC[0m`, with no extra space characters.

The JavaScript adapter supplies structural `IBuffer` reads and original `CellData` methods; it does not implement a terminal parser or substitute serializer logic. Every result comes from the actual source serializer. Rust uses a corresponding read-only `BufferAccess` fixture implementation. Native live-buffer borrowing has separate tests in `tests/serialize_native.rs`.

## Fixture format and reports

`crates/xterm-core/tests/fixtures/serialize-oracle.tsv` uses record types `palette`, `case`, `buffer` and `line`. Strings are dot-separated lowercase UTF-16 unit hex, including isolated surrogates. Empty fields are empty strings. `-` means an absent option or missing theme palette, not an empty value.

A case records dimensions, active-buffer choice, complete normal and alternate cells/wrapped flags/cursors/baseY, current attributes, modes, margins, ANSI/HTML options, selection, font configuration, theme and expected result. Cell records preserve packed content, foreground, background, extended attributes, URL identity and combined UTF-16 data. Palette records contain all 256 CSS entries; absence exercises the real headless fallback palette.

`results/serialize/oracle.json` identifies every input case, original source hash, tool version, baseline outcome, seed, fixture count and fixture SHA-256. Rust writes `ansi-differential.tsv` and `html-differential.tsv` with each case ID, status and complete actual/expected UTF-16 output or error. Counterexamples are therefore tied to their full input state in the fixture. Counts are asserted, so an empty or truncated corpus cannot pass.

Do not change expected outputs to conceal a mismatch. Keep the failing input, result and source hash. Compiler failures do not establish serializer mismatches or passing evidence. Earlier shared-core interface migration failures are retained separately under `results/serialize/failures/`. Expanded directed fixture 1254 caught a real ANSI mismatch: range 0 through 2 over a two-line buffer threw in JavaScript but silently succeeded in Rust. Its full input is `failures/case-1254.tsv`, with the pre-fix differential report retained alongside it. The reviewer requested changes to task 37; a distinct missing-next-line error fixes the behavior without altering expected data. Overall xterm.js equivalence remains NOT PROVEN until the independent terminal, browser, addon and native-platform gates pass.
