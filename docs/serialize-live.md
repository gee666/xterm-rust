# Native serialize integration

Task 88 connects the Rust serializer to the real `headless::Terminal` and `CoreTerminal`. `serialize::SerializeAddon` implements `TerminalAddon<headless::Terminal>` and can also activate directly on a `CoreTerminal`. It stores a shared terminal state handle, not copied buffers or a wrapper calling JavaScript.

`serialize_live_state` borrows current normal/alternate buffers, dimensions, current input attributes, active margins and service modes for each call. `serialize_live_html` accepts a browser host's actual selection and parsed palette. The native `serialize_as_html` method reads live font/theme options and uses the source headless palette fallback. It re-reads the theme separately for foreground and background, captures both raw values before conversion, and uses the host's default-hint string-concatenation operation. Raw font sizes are retained as `HtmlFontSize::Text`; numeric-only helper callers can use `HtmlFontSize::Number`. Raw font and global theme strings use UTF-16, including unpaired surrogates. Theme getters run only when global background is requested. State borrows are released before host getters/coercions execute. The public buffer view and numeric range are captured before those hooks. Alternate activation leaves a captured normal view unchanged, while reset reinitializes that same public view to the replacement buffer through the namespace activation listener. Holding only the old raw Buffer reference is incorrect. Both source browser and headless buffer APIs are ungated, so changing allowProposedApi must not reject serialization.

Neither activation nor serialization requires proposed APIs. Reference `browser/public/Terminal.ts:97` and `headless/public/Terminal.ts:87` expose buffer without `_checkProposedApi`; the earlier native guard was an incorrect assumption and has been removed. A cached-source probe demonstrates successful serialization with the default false flag in `source-reset-ungated-cached.json`. Before activation both methods report `Cannot use addon until it has been loaded`. Re-activation replaces the state association. Source addon disposal has no registrations to remove and retains its terminal, so raw disposal keeps serialization usable while the native host state exists. The managed addon handle removes the manager entry. Rust uses a weak state link to avoid cycles through option payloads or callbacks retaining the addon. Dropping the Rust host can release the state and produces a distinct `TerminalReleased` error; this explicit native ownership boundary is not a claim that JavaScript GC and Rust Drop have identical lifetimes. The native owner must outlive its active addon operations, and a regression verifies an options-to-addon back-reference does not leak either object.

Native mutable-borrow conflicts return typed errors and do not silently serialize missing cells. The source headless terminal has no selection-position method; `only_selection` without an explicit range reports that missing-method failure. Browser hosts supply their actual selection through `serialize_live_html`, not through a fabricated native selection.

## Preserve the source margin/cursor loss

A first Rust test assumed every serialization was lossless and failed for `CSI 2;4 r`, `CSI 3;3 H`, then `margin`. The source itself serializes the content followed by `CSI 2;4 r`. Applying that final DECSTBM homes the cursor. Original cursor `(8, 2)` becomes `(0, 0)` while margins remain `(1, 3)`.

Do not append a cursor fix to the Rust output. That would differ from upstream. Both the local JS runner and Timur's independent source check confirmed this behavior, with raw source evidence in `results/serialize/live-source.json` and `source-roundtrip-margins.json`. The original failed Rust assertion remains in `live-initial.log`.

The regression now asserts exact source ANSI, exact source cursor before and after, and all other full-state fields. The source runner asserts no other observed fields change before writing the fixture, and the Rust test asserts exactly one known loss at case 7. This is source compatibility, not a claim of lossless restoration for arbitrary terminals.
