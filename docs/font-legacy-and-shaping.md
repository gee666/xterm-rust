# Legacy ligature assertions and loaded-font terminal shaping

Full font equivalence is NOT PROVEN. This task adds verification of two previously unrun paths without changing production code or source assertions.

## Unchanged legacy Node suite

`scripts/ligature-legacy-check.mjs` transpiles the original `addons/addon-ligatures/test/LigaturesAddon.test.ts` without editing its assertions or test bodies. The runner resolves the legacy `../out-esbuild/index` import to either a source build prepared by the existing read-only oracle or the actual Rust/WASM Node bindings. It records the source file hash, WASM/binding hashes and every test outcome.

Both runs discovered, executed and passed8 tests, with zero failed, skipped or unrun tests. They cover registration, the empty initial response, unavailable or missing fonts, generic/empty families and malformed family values. The upstream suite contains500ms waits; those remain unchanged because they are part of the supplied assertions. New integration tests use promises and bounded event deadlines, not sleep-based synchronization.

The old suite mocks `font-finder`, but the current source loader uses browser font discovery. Passing that suite does not demonstrate actual installed-font discovery or shaping. Node has no browser font catalog in this run. The separate real-terminal test below closes that specific evidence gap.

## Loaded-font terminal path

`crates/xterm-web/tests/wasm_font_shaping.rs` and `tests/support/font_shaping.mjs` run a real exported Rust terminal. A real Fira Code OpenType fixture is loaded into the browser with FontFace. The font-discovery boundary returns those same bytes through a controlled Blob promise, avoiding machine-installed font and permissions dependence. This does not replace the Rust font parser or the Rust terminal engine.

With all fallback patterns disabled, the initial unshaped row is `["a===b"]`. Resolving the font read must cause the addon itself to refresh the real renderer. The resulting row is `["a", "===", "b"]`. The test checks one blob read, loaded FontFace status, the computed font family and feature settings, then verifies disposal restores the unjoined row. No test-triggered refresh is allowed between font completion and the shaped-row observation.

One Rust test passed in each Chromium148.0.7778.96, Firefox150.0.2 and WebKit26.4 on Windows. This proves the loaded-font/joiner/DOM path, not pixel-identical rasterization, permission UI behavior or native Linux/macOS execution.

## Commands

Run from a private O: worktree with Node24.15.0, Rust/Cargo1.85.1, wasm-bindgen0.2.100 and existing source dependencies. Set `TEMP` and `TMP` in separate shell assignments to the owned scratch directory. Use Cargo `-j2` and coordinate browser jobs with the integration owner.

```sh
cargo build -j2 -p xterm-font-addons --target wasm32-unknown-unknown
wasm-bindgen target/wasm32-unknown-unknown/debug/xterm_font_addons.wasm --target nodejs --out-dir tmp/font-node
SOURCE_PACKAGE_JSON=/installed/reference/package.json node scripts/ligature-legacy-check.mjs tmp/font-node/xterm_font_addons.js
WASM_TEST=wasm_font_shaping node scripts/browser-host-check.mjs
cargo clippy -j2 -p xterm-web --lib --test wasm_font_shaping --target wasm32-unknown-unknown -- -D warnings
rustfmt --edition 2021 --check crates/xterm-web/tests/wasm_font_shaping.rs
```

`WASM_BINDGEN` and `PLAYWRIGHT_MODULE` can point to existing tool/dependency installs as described by the browser-host-check skill. The legacy runner reuses the existing source oracle, which verifies its source fixture rather than silently regenerating it.
