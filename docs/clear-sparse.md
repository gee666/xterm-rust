# Sparse cursor rows during clear

Task 565 repairs one boundary in `terminal::clear_state_handle`, shared by the Rust core and headless/browser hosts. Full parser/buffer equivalence and the final quality/platform matrices remain open.

The unchanged headless and browser `clear` implementations first dispose markers, then move the current row to slot zero, even when that row is JavaScript `undefined`. They set the logical line count to one, reset viewport offsets and cursor row, fill the remaining viewport with default-attribute blank rows and emit scroll. The cursor column and terminal attributes are retained. Rust previously converted the optional current row to `MissingLine`, stopping before those later effects. The repair transfers the `Option<LineRef>` directly to the circular list. No row is invented, no error is swallowed, and callback failures still propagate.

`clear-sparse-oracle.mjs` runs the two unchanged original public clear tests and generates 280 deterministic cases. These use normal/alternate buffers, one/four rows, columns zero/five, dense/hole/truncated/empty/outside-current layouts, and direct mutation or marker callbacks that reset, resize, activate the other buffer or throw. Scroll listeners can also throw. Each case records both buffers' packed cells, UTF-16 strings and extended attributes, terminal modes, cursor/viewport/margins, callback-time snapshots, row identity, marker disposal and exact source sentinel identity. Internal sparse mutations are explicit boundary inputs, not ordinary write-stream coverage. Shared source/native snapshot helpers now represent absent rows by `-`; dense records are unchanged.
