# Link mouseup geometry ordering

Task405 restores the source Linkifier's early return when no current link exists. Previously, Rust evaluated its coordinate callback for every mouseup, even without a hovered link. In a real terminal this reads DOM geometry and renderer dimensions. Host getters or failures were observable on unlinked mouseup, unlike the source.

`links/browser_linkifier.rs` now checks current-link presence before converting the event or evaluating coordinates. The short RefCell borrow ends before any callback runs. With a current link, coordinates are still evaluated once, an absent position still prevents activation, and a thrown coordinate error retains its original JavaScript identity. This does not change provider ordering, link equality, hover state or the terminal's geometry implementation. No dependency, unsafe code or JavaScript terminal delegation was added.

## Regression and source evidence

The new private module `tests/linkifier/mouseup.rs` shares the existing BrowserLinkifier suite's provider and link helpers. It tests seven mouseup phases. Idle, awaiting a provider reply, cleared by mouseleave and disposed controllers do not call a throwing coordinate dependency. Active-link mouseup calls it once and activates once. An invalid position calls it once but does not activate. An active coordinate failure calls it once and reaches the browser error event with the exact original thrown object. Hover/activation/leave order remains unchanged.

`scripts/link-mouseup-source.mjs` opens the original production Terminal, registers a public provider, and runs the same seven phases through its actual Linkifier DOM listeners. It injects only the Linkifier coordinate dependency to count calls, return an absent position or throw a known object. It does not replace the state machine. The shared `link-mouseup-observe.js` captures and prevents the expected synchronous error event on both sides. Other page errors remain failures. Both runners own finite deadlines and close browsers and the server in finally blocks.

The source runner verifies that the production bundle's embedded Linkifier TypeScript is byte-identical to the read-only reference file, and records bundle/map/source hashes. These are custom directed differential phases, not seven unchanged upstream test definitions or a proof of all geometry behavior. The source runner and Rust test independently assert the same phase counts, exact thrown identity and callback log.

Before the production guard, the new Chromium assertion failed at idle, with one coordinate call instead of zero. All six existing Linkifier tests passed. `results/link-mouseup/baseline.json` and `runs/` retain the complete failed report and browser log. The final source guard passes all seven Rust tests in Chromium148.0.7778.96, Firefox150.0.2 and WebKit26.4. The original seven-phase trace also passes all three engines.

## Reproduction

Use an owned O: worktree with a regular Cargo target and at most one coordinated heavy job slot. Set `CARGO_BUILD_JOBS=2`, `CARGO_TARGET_DIR` to its target directory and `TEMP`, `TMP`, `TMPDIR` under its tmp directory. Set `SOURCE_ROOT` to the existing built read-only reference, `PLAYWRIGHT_MODULE` to its node_modules/playwright/index.mjs, `NODE_PATH` to its node_modules, and `WASM_BINDGEN` to the existing 0.2.100 CLI. No dependency installation or reference junction is needed.

```sh
node scripts/link-mouseup-source.mjs
WASM_TEST=wasm_linkifier node scripts/browser-host-check.mjs
node scripts/link-oracle.mjs
cargo test --locked -j2 -p xterm-web --test links --test link_state --test osc_links_differential --test osc_links_live --test debounce --test debounce_errors --test debounce_differential --test link_replies_differential
cargo clippy --locked -j2 -p xterm-web --all-targets --all-features -- -D warnings
cargo clippy --locked -j2 -p xterm-web --target wasm32-unknown-unknown --lib --test wasm_linkifier -- -D warnings
cargo fmt --all -- --check
for package in xterm-core xterm-addons xterm-web xterm-wasm-support xterm-font-addons; do cargo fmt -p "$package" -- --check; done
```
