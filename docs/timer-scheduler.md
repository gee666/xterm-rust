# Reentrant timer scheduling

Task486 removes scheduler borrows across TimeBasedDebouncer host calls. TimerScheduler gains shared clock/request hooks and a cancellation hook that resolves the pending ID at the host's argument-evaluation boundary. Defaults preserve existing non-reentrant native scheduler implementations. BrowserTimerScheduler copies independent host handles before entering performance.now, setTimeout or clearTimeout. Its request path also releases the callback-slot borrow before reading or calling setTimeout.

The source stores updated rows before reading the clock. It sets the additional-refresh flag before requesting a trailing timer, but assigns the pending ID only after a successful request. Reentrant disposal and a nested request can install a replacement timer that the successful outer assignment overwrites. Cancellation checks whether an ID exists before looking up clearTimeout, then reads the ID after that lookup. A getter can replace or clear it. Successful cancellation clears the current slot; failed cancellation leaves the current slot and flags untouched. A trailing callback reads the clock before rendering and clears flags only after successful rendering. The repair preserves these boundaries rather than canceling or rolling back nested work.

The clock hook returns Result, so an original JavaScript getter/call error is returned through the browser adapter without changing the thrown value. The typed native clock remains f64. Raw nonnumeric clock results, nonnumeric timer identifiers, raw row values and arbitrary threshold values remain outside this change. The existing browser adapter's positive integral i32 timer-ID validation is unchanged. Browser Window/performance construction and global replacement behavior are not established here.
