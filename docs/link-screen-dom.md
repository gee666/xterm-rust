# Live link screen DOM target

Task401 fixes two production references in `terminal/link_services.rs`. The original `CoreBrowserTerminal` constructs its Linkifier with `screenElement`, and Linkifier uses that same element for listeners, pointer classes and mouse coordinates. Rust had supplied the outer terminal root to both the controller and coordinate calculation.

The production controller now receives `services.dom.screen`. Geometry reads that screen's rectangle and padding. Parsing, OSC8 discovery, callback policy and state remain in Rust. No dependency, JavaScript terminal engine or second mode/state authority was added. Existing browser Linkifier component behavior is unchanged.

## Shared source and Rust regression

`scripts/link-screen-trace.js` runs through actual opened Terminals. Both implementations first parse five unlinked characters, one linked character and an unlinked trailing delimiter. The delimiter matters because the source deliberately does not flush a new single-cell link at trimmed end-of-line.

The trace gives root and screen different padding, then records six exact DOM/callback snapshots. Root-only movement/click/leave do not invoke the screen controller. Screen movement puts the pointer class on the screen only. Bubbling screen down/up activates the link once. A nonbubbling screen leave clears its pointer and calls leave with the last movement event. Screen events dispatched after terminal disposal add no callbacks. This exercises screen-relative geometry, including screen padding subtraction, rather than accepting a pointer class on either node.

The original production bundle's embedded CoreBrowserTerminal, Linkifier, MouseCoordsService and input/Mouse sources match the read-only TypeScript files. The same six-snapshot trace and post-disposal callback log pass Chromium148.0.7778.96, Firefox150.0.2 and WebKit26.4 on Windows. These are custom directed source differentials, not six unchanged upstream test definitions.

Before either production reference changed, Chromium failed the new Rust assertion with no screen callbacks. The identical original snapshot fixture passed in all three source engines. The baseline report and exact original standalone Rust test source are retained. The patched standalone test then passed all three browsers.

The final regression lives in `tests/terminal_links/screen.rs`, a private module of the existing Terminal link suite. This shares its write/render helpers and avoids adding another Cargo target. The extra standalone target had pushed the Windows cargo-fmt command above the process argument limit. No assertion or shared JavaScript program was weakened during that move. The two existing Terminal tests now dispatch on the screen and assert exact screen pointer placement, preserving all range, click, invalidation, underline and disposal assertions. Stephanie396's third test is unchanged.

Set `SOURCE_ROOT` and `PLAYWRIGHT_MODULE` to the existing read-only built reference, `NODE_PATH` to its node_modules, and `WASM_BINDGEN` to CLI0.2.100. Set temporary-directory variables under the owned worktree. Browser runners close their server and browsers in finally blocks.
