# Serialize public API mapping

Reference declarations are `source_repo/addons/addon-serialize/typings/addon-serialize.d.ts`. Implementation reference is `source_repo/addons/addon-serialize/src/SerializeAddon.ts`. This document separates callable native APIs, portable algorithms and missing browser bindings. Full addon equivalence is NOT PROVEN.

| Source declaration | Callable Rust implementation | Current evidence and gaps |
| --- | --- | --- |
| `new SerializeAddon()` | `xterm_core::serialize::SerializeAddon::new` | Native lifecycle tests in `serialize_live.rs`. No exported WASM SerializeAddon class yet; task 131 owns it. |
| `activate(terminal)` | `TerminalAddon<headless::Terminal>::activate`; `headless::Terminal::load_addon` calls this on the actual terminal | Task 88 native live activation/reactivation and managed disposal tests. Native state is linked weakly, not a copied screen. Rust host ownership must outlive addon operations; releasing it yields TerminalReleased rather than claiming JS GC parity. Browser Terminal/loadAddon activation still task 131. |
| `serialize(options?)` | `SerializeAddon::serialize(&SerializeOptions) -> Result<Vec<u16>, AddonSerializeError>` | Native defaults are explicit `SerializeOptions::default()`. Tasks 37/87 verify ANSI algorithm/source outputs; task 88 verifies actual Rust writes and restore traces. No JS-callable serialize binding yet. |
| `serializeAsHTML(options?)` | `SerializeAddon::serialize_as_html(&HtmlOptions)` | Callable native HTML method, UTF-16 output and live options. Task 88 ordering/coercion review is in progress. Native headless has no selection API, matching source headless failure for selection-only requests. Browser selection/theme binding is not implemented yet. |
| `dispose()` | `TerminalAddon<headless::Terminal>::dispose`; managed `AddonHandle::dispose` removes manager registration | Source raw dispose retains terminal and does nothing else; native raw disposal keeps serialization usable while the native host state exists. Dropping the Rust host is an explicit ownership boundary documented in serialize-live.md. Task 88 tests both raw and managed cases. Browser disposal task 131. |
| `ISerializeOptions.range` | `SerializeOptions.range: Option<LineRange>` | Inclusive resolved integer rows. Overrides scrollback and excludes final cursor positioning. Standard valid native integer ranges tested. JS Number and Marker overload conversion is not implemented by this struct. |
| `ISerializeOptions.scrollback` | `SerializeOptions.scrollback: Option<isize>` | None/all, zero, negative and oversized integer counts are implemented and tested. NaN, infinities and fractional JS values require task 131's binding conversion. Do not mark that boundary covered by integer algorithm tests. |
| `ISerializeOptions.excludeModes` | `SerializeOptions.exclude_modes: bool` | Native default false; suppresses both modes and margins. Source-output and real engine assertions retained. JS property access/coercion task 131. |
| `ISerializeOptions.excludeAltBuffer` | `SerializeOptions.exclude_alt_buffer: bool` | Native default false; normal-first/active alternate orchestration tested. JS property access/coercion task 131. |
| `ISerializeRange.start/end: IMarker \| number` | `LineRange { start: usize, end: usize }` for already-resolved native rows | No native implicit marker overload is claimed. Marker lifetime and JS Number behavior must be resolved in task 131; discarded/disposed/negative marker rows need explicit source checks. |
| `IHTMLSerializeOptions.scrollback` | `HtmlOptions.scrollback: Option<isize>` | Native integer clamp/range dispatch implemented. JS numeric boundaries remain task 131. |
| `IHTMLSerializeOptions.onlySelection` | `HtmlOptions.only_selection: bool`; portable `serialize_html` and `serialize_live_html` accept explicit `Option<CellRange>` | Portable selection geometry tested by tasks 103/87. Those functions do not prove an actual browser selection is wired. Native headless method reports the absent selection method; browser task 131 must supply real selection. |
| `IHTMLSerializeOptions.includeGlobalBackground` | `HtmlOptions.include_global_background: bool` | Native reads live options; raw UTF-16 and callback/coercion order under task 88 review. Actual browser theme palette and global option access require task 131. |
| `IHTMLSerializeOptions.range` | `HtmlOptions.range: Option<HtmlRange>` | Overrides onlySelection and scrollback. Native/portable tests cover start-column and inclusive row boundaries. JS getters/numeric conversion remain task 131. |
| `ISerializeBufferRange.startLine/endLine/startCol` | `HtmlRange { start_line: usize, end_line: usize, start_col: usize }` | Resolved integer native coordinates only. Final column remains terminal cols as upstream. No implicit JS conversion claim. |

All native implementation paths are under `crates/xterm-core/src/serialize/`. Native callable wrapper methods are in `addon.rs`; ANSI orchestration is in `terminal.rs`; HTML dispatch is in `html.rs`. `serialize_buffer`, `serialize_terminal`, `serialize_html` and `serialize_live_html` are Rust helper functions, not evidence of a JS addon export.

Task 131 owns `crates/xterm-web/src/addons/serialize.rs`, any minimal JS addon facade, actual Rust-backed browser Terminal activation, JS option/marker/error representation, selection/theme integration and browser test reuse. It has not exported those methods yet. Source original browser results, including the observed 120 source serialize browser cases across three engines, are baseline evidence only and must not be recorded as Rust binding coverage.
