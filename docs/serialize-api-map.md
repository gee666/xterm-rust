# Serialize public API mapping

Reference declarations are `source_repo/addons/addon-serialize/typings/addon-serialize.d.ts`; source behavior is `source_repo/addons/addon-serialize/src/SerializeAddon.ts`. This map describes integrated main `224d1b33`. It replaces the older native-only map that incorrectly said no WASM export existed. Full addon equivalence remains NOT PROVEN.

The supported JavaScript entry point is `browser/xterm.mjs`. Its `SerializeAddon` subclass retains `_terminal` in the JS heap, while the Rust binding keeps a weak native reference. Methods execute Rust serialization over the actual engine, not xterm.js. See [browser-serialize.md](browser-serialize.md) for exact raw contract repairs, retained failures and ownership evidence.

| Source contract | Native Rust representation | Callable browser representation and remaining limits |
| --- | --- | --- |
| `new SerializeAddon()` | `xterm_core::serialize::SerializeAddon::new` | Exported WASM class plus supported ownership subclass. No source engine delegation. |
| `activate(terminal)` | `TerminalAddon<headless::Terminal>::activate`; actual headless `load_addon` | Exported `activate` connects to the live Rust terminal. Native host lifetime is explicit; browser ownership uses the existing addon-manager WeakMap. Arbitrary structural/replaced host methods are not fully honored. |
| `serialize(options?)` | `serialize(&SerializeOptions) -> Result<Vec<u16>, AddonSerializeError>` | Rust WASM `serialize` reads JS options in phases and returns UTF-16 output. Normal/alternate buffers, cursor attributes, modes and margins use shared portable Rust. Raw ranges/coercion/accessor/error phases remain346/322. |
| `serializeAsHTML(options?)` | `serialize_as_html(&HtmlOptions)` | Rust WASM reads the live public buffer view, actual selection and ThemeService. Native headless selection-only serialization reports its absent selection method. Full palette identity/reentry and arbitrary method replacement remain incomplete. |
| `dispose()` | Raw addon disposal keeps the native weak host; managed disposal removes registration | Source empty-dispose semantics preserve later usability while the host is retained. Chromium forced-GC evidence covers specific unreachable loaded cycles; Firefox/WebKit forced GC and broader lifecycle/host mutation remain346. |
| `ISerializeOptions.range` | `Option<LineRange>` of resolved integral rows | Number/marker bounds are read at browser phases; inclusive range overrides scrollback and excludes final cursor positioning. Typed native ranges are not arbitrary JS values. |
| `ISerializeOptions.scrollback` | `Option<isize>` | Browser preserves additional fractional/nonfinite/coercion cases through its raw option reader. The native integer field alone cannot prove those semantics. See the browser guide and scoped numeric documents. |
| `excludeModes`, `excludeAltBuffer` | Explicit boolean fields, default false | Browser raw option reads precede the corresponding later serialization phases. Suppressing modes also suppresses margins. Full accessor/reentrant order still needs the complete346 audit. |
| `ISerializeRange.start/end: IMarker \| number` | Already-resolved `LineRange {start, end}` | Real marker-line getters and raw values cross the browser boundary. Invalid JS array-length differences fail after both marker reads. Additional arbitrary coordinate objects and mutation remain open. |
| `IHTMLSerializeOptions.scrollback` | `Option<isize>` | Browser numeric/coercion behavior is not reduced to the native integer type. Latest scoped repairs must be distinguished from the older retained failing numeric corpus. |
| `onlySelection` | `bool`; portable HTML functions accept `Option<CellRange>` | Real browser selection supplies end-exclusive bounds. Explicit range takes precedence. A helper supplied with a rectangle is not evidence of live selection wiring; actual-terminal browser tests are linked separately. |
| `includeGlobalBackground` | `bool` with live native options | Browser uses real theme/default palette and raw header concatenation. Arbitrary replacement and reentrant palette-array identity remain open. |
| `IHTMLSerializeOptions.range` | `Option<HtmlRange>` | Browser reads bounds and retains the selected public view at the source phases. Reset can retarget that view while alternate activation does not retarget a captured normal view. Full raw objects/aliases remain open. |
| `ISerializeBufferRange.startLine/endLine/startCol` | Resolved `usize` coordinates | Browser handles additional NaN/nonfinite/fractional/reversed numeric cases with source-derived checks. Native unsigned fields are a representation difference, not a claim to accept every JS coordinate. |

Portable algorithms and native lifecycle live under `crates/xterm-core/src/serialize/`. Browser parsing/dispatch/view integration live under `crates/xterm-web/src/serialize_addon/`. The mandatory `browser/xterm.mjs` ownership subclass is glue, not a second serializer.

The [addon coverage audit](addon-coverage-audit.md) links these modules, all declaration owners and all original suite/support paths to retained evidence. Historical unchanged original suites pass120/120 against both source and Rust, while `results/serialize-browser/verification.json` explicitly retains a failed raw-numeric corpus case. Later scoped repairs do not retroactively change that receipt. Full individual assertion reconciliation, raw/error/GC closure and final integrated matrices remain tasks346/322/328. Infinite non-progressing source loops are recorded as safety/compatibility decisions, never silently counted as equivalent passes.
